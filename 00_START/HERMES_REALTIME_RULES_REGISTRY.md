## ПРИНЦИП

Пользователь меняет правила обычным языком. Hermes сам понимает что и где.

```
Пользователь: «цена теперь 25 000 за м²»
Hermes: preview → пользователь подтверждает → сохраняет → audit log.
```

## 2. WORKFLOW ИЗМЕНЕНИЯ

```
Пользователь сказал
       │
       ▼
  Hermes понял намерение
       │
       ▼
  Показал preview: что было → что станет
       │
       ▼
  Пользователь подтвердил?
     Да → сохранить + audit log + статус confirmed
     Нет → отмена
```

---

## 3. ПРАВИЛА НАДЁЖНОСТИ

| Правило | Описание |
|---------|----------|
| Preview first | Сначала показываю изменение, потом применяю |
| Draft → confirmed | Новое значение = draft до подтверждения |
| Audit log | Каждое изменение записывается |
| Архив | Старые значения не удаляются, а архивируются |
| Старые заказы | Не пересчитываются автоматически |
| Спрашивать | Если не уверен — спрашиваю |
| Опасно | Stop condition, требую отдельное подтверждение |
| Production | Только отдельной командой |

---

## 4. ЧТО НЕ МЕНЯТЬ АВТОМАТИЧЕСКИ

- Старые заказы — без явной команды «пересчитай»
- Удалённые значения — только архивировать
- Production-файлы в E:\РАБОТА — без подтверждения
- .env, токены, ключи — никогда
