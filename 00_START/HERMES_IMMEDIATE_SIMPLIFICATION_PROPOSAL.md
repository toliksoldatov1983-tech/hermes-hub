# HERMES IMMEDIATE SIMPLIFICATION PROPOSAL

5 быстрых улучшений без риска. Ничего не внедрять — только предложить.

---

## 1. Единая команда «Новый заказ»

**Сейчас:** пользователь пишет заказ свободным текстом, Hermes разбирает.

**Предложение:** команда `/order` или фраза «Новый заказ» запускает intake-режим.

**Польза:** быстрее, меньше ошибок, сразу понятен контекст.

**Риск:** минимальный — только UI/команда, не меняет логику.

---

## 2. Единый формат короткого заказа

**Сейчас:** заказ может быть в любом формате.

**Предложение:** шаблон:
```
Заказ: <имя>
Цвет: <...>
Материал: <...>
HxW — Qty
```

**Польза:** предсказуемый парсинг, меньше disputed rows.

**Риск:** минимальный — шаблон в подсказке, не обязателен.

---

## 3. Единый статус проекта на главном экране

**Сейчас:** статус разбросан по memory/контексту.

**Предложение:** команда `/status` показывает:
- Malyarka: READY_FOR_NEXT_REAL_ORDER
- Telegram: DRY-RUN RC CLOSED
- Tests: 809 passed
- E:\РАБОТА: connected

**Польза:** мгновенный обзор всех линий.

**Риск:** никакой — read-only.

---

## 4. Кнопка «Что дальше?»

**Сейчас:** NEXT_TASK в файле, нужно читать.

**Предложение:** команда `/next` или кнопка «Что дальше?» показывает:
- Текущий статус
- Следующий крупный блок
- Что ждёт approval
- Что можно сделать безопасно прямо сейчас

**Польза:** не нужно помнить контекст между сессиями.

**Риск:** никакой — только читает NEXT_TASK.md.

---

## 5. Автоматический отчёт после каждого goal

**Сейчас:** отчёт создаётся вручную.

**Предложение:** после каждого выполненного goal автоматически создавать:
- Краткий close report
- Обновление ACTIVE_CONTEXT
- Обновление NEXT_TASK

**Польза:** всегда актуальный статус, меньше рутины.

**Риск:** минимальный — создаёт markdown, не меняет production.
