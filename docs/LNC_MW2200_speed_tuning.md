# Безопасное повышение подачи реза на LNC MW2200 для 2D и 3D обработки

## Executive summary

На вашем станке с LNC MW2200A скорость резания ограничивается не одной-двумя настройками, а минимумом из нескольких уровней ограничений: активный AIC-профиль, глобальные лимиты G01, ограничения по осям, логика прохождения углов и коротких сегментов, а также режимы точной остановки и сглаживания. Сам контроллер MW2200A — это 3-осевой pulse-command контроллер с одним каналом траектории, VGA-выходом и поддержкой ReCON, а разделы параметров скорости и high-speed/high-precision в системе прямо предназначены для настройки скорости, ускорения и качества траектории.

По вашему экрану уже видно ключевую вещь: в профиле CABINET стоят существенно более «медленные» path-параметры, чем в DOOR. В частности, у CABINET низкие 5mm Arc Max Feedrate, Arc Clamping Min Feedrate, Corner Referential Feedrate и ниже 1st Path Max Cutting Feedrate. Это означает, что прежде чем трогать глубокие системные параметры, надо сначала проверить, какой AIC-профиль реально активен, и испытать отдельный тестовый профиль для 2D и 3D. После изменения значений LNC требует повторно выбрать профиль через PROG → Program Check → SEL AIC, иначе изменения не вступят в силу.

Для вашего конкретного 3D-файла главный вывод такой: он построен из многих коротких отрезков G1, а не из G2/G3. В присланном фрагменте типичная длина сегмента — менее 1 мм, медиана около 0,58 мм, средняя около 0,93 мм, минимум около 0,14 мм. При подаче F12000 это означает, что контроллеру часто приходится обрабатывать следующий сегмент каждые 0,7–4,7 мс. Поэтому на 3D сильнее всего влияют corner handling, ускорение/замедление, сглаживание, точная остановка G61/G64, curve fitting, лимиты по Y/Z, а дуговые параметры важны в основном для программ с реальными G2/G3. Это и объясняет, почему на 3D станок может ехать намного медленнее заданного F. При этом LNC отдельно поддерживает AIC-II профили высокоскоростной/высокоточной обработки и параметр curve fitting tolerance, а также пользовательский параметр curve surface cutting feedrate speed fix именно для криволинейных поверхностей.

Практический приоритет такой. Для 2D сначала поднимают потолок подачи и угловую скорость: 1st Path Max Cutting Feedrate, глобальный G01 max speed, затем Corner Referential Feedrate, затем — при необходимости — линейное ускорение реза, и только после этого дуговые параметры, если программа реально содержит G2/G3. Для 3D приоритет другой: сначала проверить активный профиль, режим G64, отсутствие лишнего exact stop, затем Corner Referential Feedrate, глобальный G01 max speed, лимиты Y/Z, после этого аккуратно уменьшать Cutting Linear Acc/Dec Time, а параметры Curve Fitting Tolerance и Curve surface Cutting feedrate speed fix использовать уже как второй этап. В обоих случаях не следует сразу менять низкоуровневые servo loop параметры и не следует опускать время разгона слишком резко, потому что документация LNC прямо предупреждает: чем меньше время Acc/Dec, тем быстрее разгон, но тем выше риск вибрации и ошибок по параметрам.

Неопределённости, которые пока нельзя считать известными: мощность приводов, тип привода рейка/ШВП, масса портала, closed-loop/open-loop конкретной механики, реальные лимиты осей Y и Z, а также то, какой профиль AIC активируется перед запуском программы. Пока это неизвестно, безопасная стратегия — не копировать вслепую DOOR в CABINET, а сделать отдельный профиль и идти короткими шагами с воздушным прогоном и записью диагностики.

## Что именно сейчас ограничивает скорость

LNC MW2200A относится к линейке деревообрабатывающих контроллеров; по официальной странице это 3 оси, 1 Control Path, VGA Video Output, поддержка ReCON. В руководстве MW-серии сказано, что в системе есть отдельные страницы Speed setting и High-speed & high-precision, причём первая отвечает за скорости/ускорения по осям, а вторая — за параметры пути и осей, влияющие на качество и скорость обработки. Для MW2200A руководством также отмечено, что раздел servo parameters рассчитан на bus drive, а pulse driver для прямой такой настройки не подходит.

По присланному экрану видно два AIC-профиля: CABINET и DOOR. У CABINET на path-параметрах стоят значения: Linear 500, Bell 80, 5mm Arc 150, Arc Clamping Min 1, Corner Referential 80, 1st Path Max Cutting Feedrate 10000. У DOOR: Linear 500, Bell 80, 5mm Arc 3000, Arc Clamping Min 50, Corner Referential 200, 1st Path Max Cutting Feedrate 15000. Это уже само по себе объясняет, почему один профиль может ехать заметно быстрее другого на одной и той же механике.

В документации LNC AIC-II эта страница описана как набор до 40 материалов/профилей с индивидуальными параметрами high speed / high precision. Для AIC-II доступны, в частности, Cutting linear ACC/DEC time, Cutting bell shape ACC/DEC time, Cutting smooth ACC/DEC time, Circular clamp speed, Circular clamp min speed, Corner reference speed, а также feedforward и loop gains. После изменения значения профиль нужно переизбрать через Select AIC, чтобы изменения применились.

Ваш G-code-фрагмент для 3D содержит длинную последовательность G1 с малыми изменениями прежде всего по Y и Z. Сам по себе комментарий (FEED RATES IN INCHES PER MINUTE) ничего не переключает; единицы задаются командами G20/G21, а единицы подачи — G94/G95. По LNC, G21 должен задаваться отдельным блоком в заголовке программы, а G94 определяет единицы F для G01/G02/G03 как мм/мин или дюйм/мин в зависимости от системы единиц. По G61/G64 LNC прямо указывает: G61 — exact positioning, G64 — общий режим резания, и G64 является режимом по умолчанию, пока не был объявлен G61.

Это важно по двум причинам. Во-первых, если в системе или в программе случайно активирован G61 либо exact stop, контроллер будет заметно тормозить на переходах. Во-вторых, в ваших 3D-данных короткие сегменты сами по себе вынуждают planner снижать фактическую скорость. Для такой траектории наиболее вероятные ограничения — угловая обработка, acceleration/deceleration, curve fitting, exact stop, Y/Z axis limits, а не 5mm Arc Max Feedrate, потому что этот параметр относится прежде всего к дуговой интерполяции. Документация также описывает Curve fitting tolerance с диапазоном -1…10 мкм, где -1 означает выключено, а пользовательский параметр Curve surface Cutting feedrate speed fix позволяет отдельно включать коррекцию подачи на криволинейной поверхности.

Дополнительный системный потолок для любой линейной резки задаёт параметр 1004 G01 MAX. SPEED OF LINEAR CUTTING. Руководство прямо указывает его как глобальный максимум линейной резки, а страницы MW-серии отдельно показывают, что Speed setting содержит поосевые G00/G01 лимиты. Поэтому фактическая подача всегда будет не выше минимума из: F в программе, AIC profile max cutting, parameter 1004, Y/Z axis speed limits, допустимой динамики траектории.

## Приоритетные параметры для 2D и 3D

### Базовые принципы выбора параметров

Для 2D и 3D приоритеты различаются. На 2D-профилях и пазах с длинными прямыми участками выше отдача от увеличения максимально разрешённой подачи и умеренного уменьшения времени разгона. На 3D-рельефе с короткими G1 важнее способность пройти последовательность коротких блоков без постоянного торможения, то есть более критичны угловая скорость, непрерывный режим резания, curve fitting, Y/Z limits и плавная кинематика. Это соответствует структуре AIC-II и G64/G61 в LNC.

### Приоритет для 2D

| Приоритет | Параметр | Почему важен для 2D | Что делать сначала |
|-----------|----------|---------------------|-------------------|
| Высокий | 1st Path Max Cutting Feedrate | Если он ниже F в программе, контроллер режет не быстрее профиля | Поднять до уровня реальной целевой подачи |
| Высокий | 1004 G01 MAX. SPEED OF LINEAR CUTTING | Глобальный предел линейной резки | Проверить, что он не ниже целевой подачи |
| Высокий | Corner Referential Feedrate | Уменьшает торможение в углах и на переходах | Поднимать умеренно, без рывка |
| Средний | Cutting Linear Acc/Dec Time | Быстрее добирается до целевой подачи на прямых | Уменьшать пошагово |
| Средний | 5mm Arc Max Feedrate | Важен, если программа реально использует G2/G3 | Поднимать только если есть дуги |
| Средний | Arc Clamping Min Feedrate | Не даёт излишне проседать на дугах | Поднимать только вместе с Arc Max |
| Низкий | Curve Fitting Tolerance | Для 2D чаще не самый главный фактор | Не трогать, если 2D и так гладкий |

### Приоритет для 3D

| Приоритет | Параметр | Почему важен для 3D | Что делать сначала |
|-----------|----------|---------------------|-------------------|
| Очень высокий | Активный SEL AIC профиль | Если активен CABINET, вы уже стартуете с более жёсткими ограничениями | Проверить и зафиксировать активный профиль |
| Очень высокий | G64 и отсутствие лишнего exact stop | Exact stop резко тормозит на коротких блоках | Явно задать G64; проверить G61/G09 и флаг exact check |
| Очень высокий | Corner Referential Feedrate | Главный параметр против падения скорости на коротких сменах направления | Поднимать раньше разгона |

| Средний | Cutting Bell / Smooth Acc/Dec Time | Меняет форму нарастания ускорения и мягкость | Трогать после corner/linear |
| Низкий | 5mm Arc Max / Arc Clamping Min | Для вашего файла из G1 — не главный фактор | Оставить на потом |

Они опираются на структуру LNC AIC-II, диапазоны параметров в руководстве и на то, что заводской профиль DOOR уже использует более высокие значения без выхода за рамки системы. Диапазоны AIC-II для path-параметров документированы: Linear/Bell/Smooth — 0…1000 мс, Corner reference speed — 0…200000000 um/min, round speed lock и minimum — 100…200000000 um/min, Curve fitting tolerance — -1…10 мкм.

## Что делать с поосевыми лимитами

Ваш 3D-файл нагружает в основном Y и Z, поэтому именно они должны проверяться первыми. Руководство MW-серии говорит, что Speed setting содержит поосевые ускорения/замедления, G00 max speed, G01 max speed, а High-speed & high-precision делится на path parameters и axis parameters. При этом на вашем фото видна только страница для X: X Axis Cutting Feed Linear Acc/Dec Time in Position Mode = 80, X Axis Cutting Feed S Curve Acc/Dec Time in Position Mode = 0, а X Axis Rapid Max Feedrate отличается между профилями. Но для решения именно вашей 3D-проблемы этого недостаточно — нужны Y и Z.

Практическое правило здесь такое. Если целевая 3D-подача — 12000 мм/мин, а Y/Z по своим G01 max или axis-accel параметрам ограничены ниже того, что требует траектория, то никакая path-настройка не заставит станок реально ехать быстрее. Поэтому для Y и особенно Z действуйте осторожнее: Z обычно должна оставаться более консервативной, чем Y, потому что именно она в 3D чаще провоцирует ударность, перегрузку и дефекты поверхности. Это уже инженерный вывод из вашей траектории и из структуры LNC speed pages.

## Рекомендуемая процедура тестов

### Порядок испытаний

Контроллер LNC позволяет хранить разные AIC-профили и требует переизбрать профиль после изменения. Кроме того, в MDI и Program Check предусмотрены безопасные режимы проверки программы. Из-за неизвестной механики станка лучшая стратегия — не переписывать рабочий профиль, а завести отдельный тестовый профиль и идти короткими итерациями.

```
Снять backup параметров и фото всех страниц
         ↓
Проверить активный профиль через SEL AIC
         ↓
Создать отдельный test-2D или test-3D профиль
         ↓
Изменить только 1-2 параметра
         ↓
Воздушный прогон 25%
         ↓
    ┌─ Есть вибрация, alarms, толчки? ──── Да ──→ Откатить последний шаг и записать симптомы
    │
   Нет
    ↓
Воздушный прогон 50%, 75%, 100%
         ↓
    ┌─ Фактическая подача выросла? ──── Нет ──→ Проверить G64/G61, exact stop, Y/Z limits, active AIC
    │
    Да
    ↓
Контрольный рез на небольшом участке
         ↓
Записать качество поверхности и фактическую подачу
         ↓
Следующая маленькая ступень
```

### Конкретная последовательность

Сначала сделайте backup. В LNC есть штатные средства экспорта параметров и файлов, а для диагностики предусмотрены также Operation history record и Data Recorder. Для истории операций параметр 395 позволяет включить запись истории, а 653 — активировать Data Recorder.

Далее зафиксируйте исходное состояние:

1. Сфотографировать все страницы path parameters и axis parameters.
2. Сфотографировать Speed setting по X, Y, Z.
3. Сфотографировать PROG → Program Check → SEL AIC.
4. Сохранить копию тестовой программы и добавить в её заголовок явные G21, G94, G64, если их нет.

Для заголовка тестовой программы безопасно использовать такой шаблон:

```
G21
G90 G94 G64
G49 G40 G80
G54
```

Это соответствует правилам LNC: G21 задаётся отдельным блоком до системы координат, G94 определяет единицы подачи для G01/G02/G03, G64 включает общий непрерывный режим резания.

После этого:

| Шаг | Что меняем | Как тестируем |
|-----|-----------|---------------|
| Первый | Выбор test-профиля, без изменения сервопараметров | Воздушный прогон 25% |
| Второй | Только Max Cutting и Corner Reference | Воздух 25% → 50% → 75% → 100% |
| Третий | Только Linear Acc/Dec | Повторить тот же маршрут |
| Четвёртый | Только Curve Fitting или Curve Surface Speed Fix | Малый фрагмент 3D, отдельный тест |
| Пятый | Контрольный рез по материалу | Сравнить шум, поверхность, фактическую скорость |

### Что контролировать во время каждого теста

Смотреть нужно не только на «процент подачи» на экране, а на фактическое поведение машины. Для этого записывайте:

- фактическую подачу на экране и её стабильность;
- есть ли резкие просадки на переходах;
- звук портала и оси Z;
- вибрацию, дрожание, «песню» на Y;
- alarms / warnings / MOT-сообщения;
- температуру привода и шпинделя после серии проходов;
- качество поверхности: волна, ступеньки, поджоги, мохра.

Если фактическую подачу экраном оценить трудно, измеряйте её по формуле:

> средняя подача = пройденное расстояние / время × 60

Например, берёте участок длиной 300 мм по Y, запускаете в воздухе, замеряете время секундомером и считаете мм/мин. Такой ручной замер иногда полезнее процента override.

## Как понять, что проблема не в AIC, а в exact stop

У LNC G61 — exact positioning, G64 — general cutting mode, причём G64 является режимом по умолчанию. Дополнительно параметр 43 FLAG OF EXACT CHECK позволяет по битам включать/выключать exact stop для G01/G00, и manual прямо говорит: для G01 режим exact stop требует не только соответствующего бита, но и G09 либо G61; отменяется он G64. Если после всех разумных изменений подача всё равно катастрофически падает на каждой точке, проверьте именно эту группу.

| Cutting Smooth Acc/Dec Time | как есть / 0–20 | как есть / 0–20 |

### Агрессивная настройка

| Группа | 2D | 3D |
|--------|----|----|
| 1st Path Max Cutting Feedrate | 12000–15000 | 12000–15000 |
| Corner Referential Feedrate | 200–300 | 220–350 |
| Cutting Linear Acc/Dec Time | 300–350 мс | 300–350 мс |
| Cutting Bell Acc/Dec Time | 60–100 мс | 60–100 мс |
| Cutting Smooth Acc/Dec Time | 20–40 мс | 20–40 мс |
| 5mm Arc Max Feedrate | 2000–3000 | если в траектории есть дуги |
| Arc Clamping Min Feedrate | 50 | если в траектории есть дуги |
| Curve Fitting Tolerance | 3–5 мкм | 5–8 мкм только под контролем качества |
| Curve surface speed fix | 0 или 1 | 1 |

Главное ограничение здесь — не теория контроллера, а механика вашего станка. Документация LNC действительно допускает большие диапазоны параметров, однако она же прямо указывает, что уменьшение времени ускорения делает разгон быстрее, но увеличивает вероятность вибрации и ошибок настройки. Из этого следует практический предел: не опускать path linear accel резко ниже 300 мс, пока не будут известны Y/Z limits, привода и масса портала. Это осторожный инженерный вывод, а не формальная заводская цифра.

## Какие фото и данные надо собрать дальше

### Обязательный набор

Сейчас у нас нет самого важного — поосевых страниц Y и Z, а именно они критичны для вашего 3D-файла. Руководство MW-серии прямо разделяет настройки на Speed setting, High-speed & high-precision, Servo parameters и Advanced parameters; менять нужно в первую очередь первые две группы, а deep servo tuning для pulse driver — не первоочередная задача.

Сфотографируйте по порядку:

| Экран | Что должно быть видно |
|-------|----------------------|
| PROG → Program Check → SEL AIC | активный профиль перед запуском |
| Maintenance → Parameters → Speed setting | X/Y/Z G00 max, G01 max, rapid accel, cutting accel |
| Maintenance → Parameters → High-speed & high-precision → Path parameters | весь профиль, включая строки ниже текущего кадра |
| Maintenance → Parameters → High-speed & high-precision → Axis parameters | X/Y/Z оси целиком |
| Экран в реальном запуске | programmed feed, actual feed, override %, alarms/warnings |
| Диагностика/история | если включите Operation history и Data Recorder |
| G-code | 50–100 строк 2D-файла и 100–200 строк 3D-файла из одной рабочей зоны |

По G-code нужны именно такие фрагменты:

- начало программы до первого реза;
- 50–100 строк в зоне, где станок «ползёт»;
- если есть 2D-контур, 20–30 строк с типичными переходами;
- любой участок, где есть G2/G3, если он используется.

### Что отдельно зафиксировать при тестах

Во время каждого прогона записывайте в таблицу:

| Дата | Профиль | Изменённые параметры | Материал | Инструмент | F в программе | Override | Фактическая подача | Шум/вибрация | Качество |
|------|---------|---------------------|----------|------------|---------------|----------|-------------------|-------------|----------|

Даже простая такая таблица через 5–6 тестов даст больше пользы, чем разовые «ощущения».

## Наблюдение экрана в реальном времени на ПК

У MW2200A по официальной спецификации есть VGA video output, а также поддержка ReCON. Для реального дублирования именно экрана самый надёжный способ — видеозахват VGA, потому что он показывает ровно то же, что отображает панель, включая feed, alarms и текущие страницы параметров. Сетевой ReCON можно использовать как дополнительный канал, но именно для непрерывного «зеркала» экрана VGA-путь предсказуемее.

Рекомендуемая схема:

```
LNC MW2200A VGA OUT
        ↓
Активный VGA splitter 1x2
   ↙          ↘
Штатный      Активный VGA to HDMI converter
монитор            ↓
станка       USB HDMI capture
                   ↓
               ПК с OBS
```

Практически это выглядит так:

- активный VGA splitter 1×2;
- активный VGA→HDMI converter;
- USB HDMI capture;
- на ПК — OBS Studio с источником «Video Capture Device».

Так вы сможете записывать экран во время тестов и потом покадрово смотреть, где именно падает подача.

## Короткий troubleshooting

### Если появилась вибрация

Самая типичная причина — слишком агрессивно уменьшили Cutting Linear Acc/Dec Time либо слишком быстро подняли Corner Referential Feedrate. Документация LNC прямо связывает уменьшение Acc/Dec с более быстрым выходом на скорость и ростом вибрации. В этом случае откатите последний шаг, а не весь профиль сразу. Обычно сначала возвращают Linear Acc/Dec на один шаг назад, и только потом уменьшают Corner.

### Если программная подача 12000, а фактически больше 300–800 не получается

Проверьте по порядку:

1. активный AIC-профиль;
2. 1st Path Max Cutting Feedrate;
3. 1004 G01 MAX. SPEED OF LINEAR CUTTING;
4. Y/Z axis G01 max и cutting accel;
5. режим G64 и отсутствие G61/G09;
6. FLAG OF EXACT CHECK;
7. включён ли Curve Fitting Tolerance;
8. не нужен ли Curve surface speed fix для 3D.

Это соответствует структуре ограничений в LNC: профиль AIC-II, глобальный G01 max speed, exact stop logic и параметры криволинейной поверхности.

### Если появляется потеря позиционирования

Так как MW2200A в этой конфигурации — pulse-command контроллер, а Servo parameters в UI для pulse driver не являются главным местом первичной настройки, симптом «потери шагов» или ухода позиции надо сначала трактовать как переагрессивную кинематику либо проблемы привода/механики, а не как повод сразу лезть в loop gains. Сначала верните последние изменения разгона и corner speed, проверьте ремни/рейку/ШВП, люфты, зацепление и только потом обсуждайте глубокую настройку приводов.

### Если поверхность стала волнистой или «рваной»

Для 3D это обычно означает одно из трёх:

1. слишком высоки corner/acceleration для данной механики;
2. слишком большой Curve Fitting Tolerance;
3. Z не успевает по динамике за Y.

В таком случае сначала уменьшите Curve Fitting, затем верните на шаг назад Linear Acc/Dec, и только потом трогайте corner speed.

### Если появились MOT alarms

Снимите фото точного кода MOT. По LNC многие ошибки связаны именно с выходом параметров за допустимый диапазон, несоответствием G01 max speed, rigid tapping limits или некорректной комбинацией параметров/режимов. Без конкретного MOT-кода гадать не стоит.

## Приоритет источников и итоговый вывод

Для настройки такого станка имеет смысл доверять источникам в следующем порядке.

Во-первых, официальной странице LNC MW2200A: она подтверждает модель контроллера, VGA, 3 axes, 1 Control Path, ReCON.

Во-вторых, операционным и application-руководствам LNC по MW/milling series: именно они описывают SEL AIC, AIC-II, Speed setting, High-speed & high-precision, G01 max speed, Curve fitting tolerance, Curve surface Cutting feedrate speed fix, Operation history record, Data Recorder. Эти документы — главный источник для самих параметров и их диапазонов.

В-третьих, программное руководство LNC MILL: оно важно для проверки заголовка программы, G20/G21, G94, G61/G64, а также понимания того, не включён ли режим точной остановки.

Русскоязычные сайты с зеркалами и видео могут быть полезны как вспомогательные, но решения по тюнингу лучше принимать по руководствам LNC и по данным именно вашего станка, а не по чужим универсальным советам.

Итог по вашей ситуации такой. Для 2D разумно начинать с поднятия потолка подачи и угловой скорости. Для 3D ваш главный резерв — не дуговые параметры сами по себе, а правильный AIC-профиль, G64, проверка exact stop, Corner Referential Feedrate, линейный Acc/Dec и особенно лимиты Y/Z. Самый безопасный первый шаг — создать отдельный test-3D профиль, поставить в нём 1st Path Max Cutting Feedrate = 12000, Corner Referential Feedrate = 150, Linear Acc/Dec = 450, оставить Bell без изменений, явно прописать G21 G94 G64, сделать воздушный прогон и записать экран через OBS. После этого уже можно идти ступенями к Corner 200–250, Linear 400–350, а затем отдельно тестировать Curve Fitting 3–5 µm и Curve surface speed fix = 1. Такой порядок даёт наибольший шанс поднять реальную скорость без рывка в опасную зону.
